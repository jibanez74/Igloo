No. **`expo-video` will not secretly transcode, remux, or convert codecs.** It is a playback layer, not a media-processing layer. On Android TV it delegates playback to the native Android/ExoPlayer/Media3 stack, and Expo describes it as a cross-platform native video component rather than a transcoder. ([Expo Documentation][1])

But there is an important distinction:

```text
expo-video will not convert the file.
The Android/Shield audio pipeline may decode, passthrough, downmix, or fail depending on device/audio settings.
```

## What can happen with TrueHD Atmos

For a file like:

```text
MKV
Video: HEVC
Audio: Dolby TrueHD 7.1 Atmos
```

`expo-video` itself should not convert that TrueHD track to AAC, AC-3, or stereo. However, the playback path has to support **bitstream passthrough**. ExoPlayer/Media3 format support depends on the platform/device decoders and audio capabilities. Google’s Media3/ExoPlayer docs explicitly say contained audio/video sample formats must also be supported, and Dolby’s Android TV guidance points developers to ExoPlayer APIs for detecting Dolby Audio/Atmos capabilities. ([Android Developers][2])

So the real question is not “will Expo convert it?” The real question is:

```text
Will the native Android player path used by expo-video expose/pass through TrueHD Atmos correctly on Nvidia Shield?
```

That is the part I would not assume without testing.

## Your Shield + Sonos Arc setup

Your hardware setup can be capable of TrueHD Atmos passthrough, especially if the chain is:

```text
Nvidia Shield Pro
→ TV HDMI input
→ TV eARC enabled
→ Sonos Arc
```

or:

```text
Nvidia Shield Pro
→ HDMI switch/receiver
→ Sonos Arc / TV eARC path
```

But the app still has to request/play the track in a way that allows passthrough. Plex, Kodi, Emby, and similar apps usually expose explicit passthrough settings. For example, Plex users commonly need to set passthrough to HDMI for Dolby TrueHD passthrough to work instead of having the server transcode or the client decode/downmix. ([Reddit][3]) Sonos community guidance also points to enabling passthrough and eARC in the TV audio settings, with the sending device’s audio settings also mattering. ([Sonos Community][4])

## The risk with `expo-video`

The risk is **not hidden transcoding**.

The risk is that `expo-video` may not give you enough low-level Android/ExoPlayer control to force or configure passthrough behavior the same way Plex/Kodi/Emby do.

Possible outcomes:

```text
Best case:
MKV + TrueHD Atmos direct plays and Sonos reports Dolby Atmos / TrueHD Atmos.

Acceptable fallback:
Video direct plays, but audio fails; your backend transcodes only audio to E-AC-3 or AC-3.

Bad fallback:
Android decodes/downmixes to PCM/stereo or no audio, and expo-video does not expose enough controls to fix it.
```

## What I would do for Igloo

For Nvidia Shield, I would create a dedicated playback profile:

```ts
const nvidiaShieldProfile = {
  allowMkvDirectPlay: true,
  allowHevcDirectPlay: true,
  allowTrueHdPassthroughAttempt: true,
  fallbackAudioCodec: "eac3",
};
```

Then use this logic:

```text
1. If client is Nvidia Shield and user enabled passthrough:
   Try direct play for MKV + TrueHD Atmos.

2. If playback fails or the user disables passthrough:
   Keep the video stream untouched.
   Transcode only audio to E-AC-3 5.1 or AC-3 5.1.

3. If subtitles require burn-in:
   Full transcode only when necessary.
```

For the server, do **not** transcode TrueHD automatically just because the codec is TrueHD. Let the Shield profile attempt direct play first.

## Recommendation

For your specific setup, `expo-video` is worth testing, but I would not commit to it until you test these files:

```text
MKV + HEVC + TrueHD 7.1 Atmos
MKV + HEVC + E-AC-3 Atmos
MKV + HEVC + DTS-HD MA
MKV + HEVC + AC-3 5.1
MKV + HEVC + AAC stereo
```

Then check what the Sonos app reports during playback.

The most important result is whether `expo-video` can pass through **TrueHD Atmos** on the Shield. If it cannot, that does not mean the Shield cannot do it; it means your app/player path may need deeper native ExoPlayer configuration, `react-native-video`, a custom native module, or an external-player option like Kodi.
