At least from the current public `expo-video` docs: **no, there is no `app.json` / config-plugin option for enabling HDMI audio passthrough, TrueHD passthrough, tunneled playback, or ExoPlayer audio-sink behavior.**

The `expo-video` config plugin currently documents only:

```json
{
  "expo": {
    "plugins": [
      [
        "expo-video",
        {
          "supportsBackgroundPlayback": true,
          "supportsPictureInPicture": true
        }
      ]
    ]
  }
}
```

Those options affect background playback and Picture-in-Picture, not surround passthrough. Expo’s docs list only `supportsBackgroundPlayback` and `supportsPictureInPicture` as configurable plugin properties. ([Expo Documentation][1])

## What actually needs to be configured

For passthrough to work, there are usually three layers:

```text
1. Hardware / HDMI chain
2. Android TV / Nvidia Shield audio settings
3. The app/player implementation
```

### 1. Hardware chain

For TrueHD Atmos, the safest path is usually:

```text
Nvidia Shield
→ HDMI input on TV or receiver
→ eARC to Sonos Arc
```

Important: **regular ARC is not enough for TrueHD Atmos.** You need **eARC** for lossless TrueHD passthrough. Regular ARC is normally limited to Dolby Digital, DTS, and sometimes Dolby Digital Plus Atmos.

### 2. Nvidia Shield / TV settings

On the Shield, you usually want something like:

```text
Settings
→ Device Preferences
→ Display & Sound
→ Advanced sound settings
→ Available formats
→ Auto, or Manual with Dolby TrueHD enabled
```

Also check:

```text
Dolby audio processing: Off
Match content audio resolution: On, if available
```

On the TV, you usually want:

```text
eARC: On
Digital sound output: Pass Through / Bitstream / Auto
HDMI input audio format: Bitstream
```

The exact wording depends on the TV brand.

### 3. App/player implementation

This is the part that matters for `expo-video`.

`expo-video` is wrapping the native player path. On Android, that means the behavior ultimately depends on Android/Media3/ExoPlayer and the device’s audio capabilities. Google’s ExoPlayer docs state that format support depends on both container support and the underlying platform/device support for the actual audio/video sample formats. ([Android Developers][2])

For basic Dolby playback, Dolby’s Android TV guidance says that if the device supports Dolby Audio/Atmos, apps can use ExoPlayer APIs to play the content. The catch is that advanced passthrough behavior may still require lower-level player configuration. ([Dolby Professional Support][3])

## The specific missing feature

The feature you are probably thinking of is not an Expo config-plugin flag. It would be something closer to native ExoPlayer/Media3 configuration, such as:

```kotlin
DefaultRenderersFactory(context)
  .setEnableAudioTrackPlaybackParams(true)
```

or, in some players, a user-facing setting like:

```text
Enable audio passthrough
Enable tunneled playback
Prefer device decoders
Use IEC passthrough
```

Some Android TV apps expose this directly. For example, third-party player discussions around TrueHD often mention **tunneled playback** or explicit passthrough toggles. Amazon’s Fire TV documentation also describes tunnel-mode playback as a native decoder/player configuration, not a manifest or Expo-style JSON setting. ([Developer Portal Master][4])

## What this means for Igloo

With stock `expo-video`, you can probably do this:

```text
Try to direct-play MKV + TrueHD on Nvidia Shield.
Let the Android player path decide whether it can open the track.
```

But you probably **cannot** do this from `app.json`:

```text
Force TrueHD passthrough.
Enable passthrough mode.
Enable tunneled playback.
Choose IEC/raw audio output.
Configure ExoPlayer's AudioSink.
```

So your realistic options are:

| Option                                 | What it gives you                                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **Use stock `expo-video`**             | Simple Expo integration; test whether Shield passthrough works by default.                                                           |
| **Use `react-native-video`**           | Possibly more access to Android ExoPlayer behavior, but verify whether it exposes the exact passthrough/tunneling controls you need. |
| **Create a custom native Expo module** | Best control. You can configure Media3/ExoPlayer directly for Android TV.                                                            |
| **Add external player support**        | Let Kodi/VLC/Just Player handle difficult passthrough cases.                                                                         |
| **Backend fallback**                   | Direct play first; if it fails, audio-transcode TrueHD to E-AC-3/AC-3 while copying video.                                           |

## My recommendation

For your setup, I would not depend on an `expo-video` JSON setting, because it does not appear to exist.

I would implement the backend profile like this:

```ts
const nvidiaShieldProfile = {
  directPlayContainers: ["mkv", "mp4"],
  directPlayVideoCodecs: ["h264", "hevc", "vp9"],
  directPlayAudioCodecs: ["aac", "ac3", "eac3", "truehd"],
  allowTrueHdPassthroughAttempt: true,
  fallbackAudioCodec: "eac3",
};
```

Then in the app settings, expose your own toggle:

```text
Audio passthrough: Auto / Try passthrough / Force compatible audio
```

For now, that toggle would control **server behavior**, not Expo internals:

```text
Try passthrough:
  Serve MKV directly with TrueHD untouched.

Force compatible audio:
  Copy video.
  Transcode TrueHD to E-AC-3 or AC-3.
```

If stock `expo-video` passes TrueHD correctly on your Shield, you can keep it. If Sonos reports PCM/stereo/no audio instead of Dolby Atmos, you will likely need native Android player work, not an Expo plugin setting.
