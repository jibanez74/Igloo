### 3.1 App shell and boot

**M1 — Unknown URLs render bare "Not Found" text with no shell.** `/does-not-exist`
shows the TanStack Router default (`40-router-not-found-dark-desktop.png`): a
single unstyled line at the top-left, no sidebar, no header, no way back.
The router has no `defaultNotFoundComponent` (`web/src/main.tsx` /
`routeTree`). Add one that renders inside the authenticated shell with the same
"Error / Back to …" card the detail pages use (`MediaNotFound`).

**M2 — Boot splash lingered over the rendered app (dev, intermittent).** In 3 of
roughly 12 fresh page loads at 390 px the `#initial-splash` overlay stayed
visible and dimmed the already-rendered app for more than 3 s
(`05-auth-login-dark-mobile.png`, `14-home-dark-mobile.png`,
`15-home-dark-mobile-full.png`; compare the clean retakes `14b-` / `15b-`).
Because the overlay is `position: fixed; z-index: 9999` and only gets
`pointer-events: none` once `html[data-app-ready]` is set (`src/assets/boot.css`),
a lingering splash blocks all input. The removal is a 260 ms `setTimeout` inside
an effect whose cleanup clears it (`web/src/AppBoot.tsx`), so any remount in
that window cancels the removal; the element was also still present in the DOM
several seconds after boot on other loads (visible in the accessibility
snapshot). Not reproduced in a production build, so treat as "verify in prod":
remove the splash on `transitionend` of the opacity fade with a watchdog
timeout outside React, or remove it directly from `main.tsx` after the first
render rather than from an effect cleanup. Also give the element
`aria-hidden` once ready so the `role="status"` text is not announced twice.

**m1 — Notifications popover is a near-empty card.** `19-shell-notifications-dark-desktop.png`:
a 320 px panel whose only content is "You're all caught up." The panel is taller
than its content needs. Consider a compact empty state with an icon, or hide
the "Notifications" heading when there is nothing to list.

**p1 — Sidebar collapse.** Works (47 px rail, `18b-shell-sidebar-collapsed-dark-desktop.png`).
No issue; the mid-transition frame was discarded.

### 3.3 Home

**m2 — Poster title overlay collides with poster artwork.** The title/year block
sits on a 7 rem gradient (`h-28 … from-black/90 via-black/50`,
`web/src/components/shared/PosterCard.tsx`). Two-line titles start above the
dark part of the gradient and land on the poster's own lettering: "The Silence
of the Lambs", "The Prestige", "Alone" (`11-home-dark-desktop-full.png`),
"Arrival", "Avengers: Age of Ultron" (`24-movies-all-page2-dark-desktop-full.png`),
"Ghost Stories", "The Cabin in the Woods" (`26-movies-genre-horror-dark-desktop-full.png`),
and most cards on `82-search-movies-dark-desktop-full.png`. Either make the
gradient taller (start at ~45 % of the card) and darker behind the text, or
move the text below the image. Affects every poster grid (home, movies, shows,
search). Design-system §3.4 (poster card).

**p3 — Redundant section copy.** "12 movies available in recently added movies."
repeats the "12 movies" badge beside it, and the empty Albums section repeats
the sentence "Your music library is empty…" three times (subtitle, live region,
empty-state body) while taking ~400 px (`11-home-dark-desktop-full.png`,
`13-home-light-desktop-full.png`). Drop the subtitle when the badge is shown,
and use the compact `LibraryEmptyState` for empty home sections.

**p4 — Dashboard banner.** The banner promises "shared watch rooms" but no
Watch Rooms section renders when there are none (`10-home-dark-desktop.png`).
Fine as behaviour; consider a one-line placeholder so the banner copy stays true.

### 3.5 Movie detail

**m6 — Mobile action row wraps the kebab onto its own line.** At 390 px the
hero actions are `flex-wrap … justify-center`
(`web/src/components/movies/MovieDetailsHeroActions.tsx:187`): Play / Watch /
Like fill the first row and "More options" drops to a second, centered row
(`130-movie-detail-19-actions-dark-mobile.png`). On an earlier load the same
button was instead clipped at the right edge
(`35-movie-detail-19-dark-mobile-full.png`). Make the row a 2×2 grid below
`sm`, or put the kebab on the first row next to Play.

**m7 — Heading text has no separator between title and year.** The `h1`
`textContent` is `Gladiator(2000)` / `Friends(1994)` (visually spaced by CSS
gap). Screen readers announce it run together. Add a space or an `sr-only`
separator in the hero title (`DetailHero`). Design-system §1.7.

**m8 — Cast and Chapters rows clip the last card with no scroll affordance.**
`31-movie-detail-19-dark-desktop-full.png`, `32-movie-detail-7-dark-desktop-full.png`:
the eighth cast card and fourth chapter card are cut at the content edge; the
only hint is an sr-only sentence. Add a fade-out edge or visible scroll
buttons; the Cast row already has the sr-only hint, Chapters has none.

**m9 — "Show all crew" opens a nested scroll area.** The expanded list is a
fixed-height inner scroller with its own scrollbar inside the page
(`47-movie-detail-all-crew-dark-desktop.png`). Expand inline (the page already
scrolls) or move the full list into a dialog.

**m10 — Technical Details dialog.** On open the heading receives focus and shows
the focus ring around "Technical details"; the close "×" sits on the scrollbar
track and the dialog touches the top edge of the viewport
(`45-movie-dialog-technical-details-dark-desktop.png`). Keep programmatic focus
on the heading (correct for a11y) but suppress the ring for programmatic
focus (`focus-visible` already does this for mouse; the ring appears because
`tabIndex=-1` focus from a click is treated as keyboard). Give the dialog
`max-h-[90vh]` and padding so the close button clears the scrollbar.

**m11 — Edit Movie opens with the Title input scrolled to its end.** The field is
autofocused with the caret at the end, so the visible text starts mid-title
(`44-movie-dialog-edit-dark-desktop.png`). Select-all on focus, or focus
without scrolling (`preventScroll`), or focus the mode toggle instead.

**m12 — Disabled primary buttons look enabled.** "Send Request" (Request Movie,
`120-movies-request-dialog-dark-desktop.png`; Request Album/Track, `124-`,
`125-`) and "Apply Selected" (Edit Movie, `44-`) render in a slightly darker
blue that reads as a second primary action. Use the muted disabled style the
account page's "Save profile" uses (`101-settings-account-dark-desktop-full.png`).

**p5 — Error copy on detail routes.** Nonexistent IDs show the server string
"404 - The resource you requested was not found." (`39-movies-not-found-dark-desktop.png`,
`68-tv-show-not-found-dark-desktop.png`, `75-music-album-not-found-dark-desktop.png`).
Invalid IDs already have good copy ("That movie link is not valid.",
`38-movies-invalid-id-dark-desktop.png`). Map 404 to "We couldn't find that
movie." in `MediaDetailGuard` / `MediaNotFound`.

The hero menu, Playback Settings, Watch Together and Delete dialogs are clean
(`41`, `42`, `43`, `46`). In Theaters detail is clean (`37`). Light theme is
clean (`34`).

### 3.6 Video player and trailer

**M3 — Mobile control bar overlaps.** At 390 px the stream-mode pill
("Original file — English audio") wraps to three lines and sits on top of the
seek-forward button and the time readout, which is itself truncated
("0:00:00 / 2:14:0")
(`54-player-movie-19-dark-mobile.png`). Hide the pill below `sm` (the Playback

**m13 — Duplicate and inconsistent time readouts.** The seek bar shows a
current/duration pair and the transport row shows the same pair again

error state (`93-trailer-bad-key-dark-desktop.png`) drops the header bar and

### 3.11 Settings

**M4 — The save bar is always visible, translucent, and tall on mobile.** The
sticky bar (`sticky bottom-4 bg-card/85 backdrop-blur-md`,
`web/src/routes/_auth/settings/index.tsx:537`) renders even when nothing has
changed and floats over the form while scrolling; underlying text reads
through it ("Manage credentials used for metadata and interoperability." is
legible behind the bar in `100-settings-general-dark-desktop-full.png`,
`105-settings-general-light-desktop-full.png`,
`115-settings-general-savebar-dark-desktop.png`). On mobile the bar stacks two
text lines and two full-width buttons and covers ~200 px of an 844 px viewport
(`110-settings-general-dark-mobile.png`); same on Playback and Libraries

**m17 — Tab strip at tablet/mobile.** Below the `@2xl` container width the
tabs become a 2-column grid with "Users" spanning both columns
(`111-settings-general-dark-tablet.png`, `112-`, `110-`,
`108-settings-account-dark-mobile-full.png`). At 768 px the tab card is ~260 px
wide beside ~450 px of empty space, so the 2+2+1 arrangement reads as
orphaned. Let the tab card fill the content width at `@lg`, or use a
horizontally scrolling single row below `@2xl`.

**m18 — Playback page mixes per-browser and per-server scopes under one save
bar.** The three "Saved in this browser only" cards and the "Server" card share
one "Server playback settings" save bar (`103-settings-playback-dark-desktop-full.png`).

fields. Label the bar for the server card only and auto-save the browser
cards, or split the bar.

Account, Libraries, Users and the Add User dialog are clean (`101`, `102`,
`104`, `113`, `116`). Light theme is clean (`105`, `106`, `107`).

## 4. Cross-cutting suggestions

1. **One empty-state component per context.** Decide when the large
   illustrated `EmptyState` is used (first-run / nothing in the whole library)
   versus the minimal `LibraryEmptyState` (a tab or filter with no matches),
   then apply it on home, movies, music and search. Today adjacent tabs use
   different ones (m5, m16, p3).
2. **UI-owned error copy.** Four places render raw server strings
   (`02`, `39`/`68`/`75`, `91`). Add a small `errorMessageFor(status, context)`
   helper next to the fetch helpers in `web/src/lib/api.ts` so each surface
   maps status codes to sentences; keep the raw message in a `title`
   attribute or the console.
3. **Narrow-viewport action rows.** Three separate regressions at 390 px
   (hero actions m6, music header m15, player pill M3) share a cause: rows that
   rely on `flex-wrap` with content that cannot shrink. A shared rule
   ("below `sm`, action clusters become a 2-column grid; decorative pills are
   hidden") would prevent the next one. Design-system §3.1 responsive rules.
4. **Floating surfaces should be opaque.** The settings save bar is the only
   translucent floating surface and the only one with legibility problems (M4).
   The mini player and dialogs are opaque; match them.
5. **Scroll affordances for horizontal rows.** Cast, chapters, extra videos
   and season tabs all clip the last item flat. A right-edge fade
   (`mask-image` or an overlay gradient) plus visible arrow buttons on hover
   and focus would cover all of them (m8). Design-system §1.7: anything
   revealed on hover must also be reachable by focus.
6. **Poster overlay contrast.** m2 affects every grid; fix it once in
   `PosterCard` and `PosterCardSkeleton` together (the skeleton mirrors the
   gradient height).
7. **Boot robustness.** M2 is the only finding that can make the app unusable;
   even if it proves dev-only, a splash that cannot block input once React has
   rendered is cheap insurance.

## 6. Not covered and how to capture it later

- **Music detail pages, mini player, now-playing dialog, track menus,
  add-to-playlist.** The dev database has no music library path
  (`102-settings-libraries-dark-desktop-full.png` shows "No library path
  configured"). Point the Music library at `~/samba/music` in Settings →
  Libraries, run a scan, then capture `/music/album/:id`, `/music/musician/:id`,
  start a track for `MiniPlayerBar` / `NowPlayingDialog`, and open
  `TrackActionsMenu` → `AddToPlaylistDialog`.
- **Playlist detail pages (movie and music), watch room page, user
  edit/delete/reset dialogs, Delete Account.** Need a created playlist, a
  created room, a second user, and a non-admin session respectively. Create
  them in a throwaway database (`DB_PATH` override) rather than the dev DB.
- **Resume dialog, Up Next overlay, pre-roll trailers, immersive mode, HLS
  under load.** Need watch progress, an episode sequence, the trailer
  preference enabled, and real seeking. See the HLS and resume-playback
  recipes in the project memory notes.
- **Light theme for every page.** Only the key subset was captured in light;
  no light-specific defect was seen in that subset.
- **Keyboard-only pass.** Focus rings were spot-checked (visible on inputs,
  tabs, buttons) but a full tab-order pass per page was not done.
- **Production build.** All captures are from Vite dev. M2 in particular
  should be re-checked against `make build` + the embedded bundle.
