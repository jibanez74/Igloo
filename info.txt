Yes. Before you start, handle these two things as project dependencies: **the Immich API key** and **the OpenAPI spec**.

## 1. How to get an Immich API key

In the Immich web app:

1. Log in to Immich.
2. Click the user icon in the top-right corner.
3. Open **Account Settings** / **User Settings**.
4. Go to **API Keys**.
5. Create a new API key.
6. Give it a name like `Igloo Photos`.
7. Select the permissions you want.
8. Copy the key immediately and store it somewhere secure.

Immich’s docs say API keys can be created from **User Settings > API Keys**, and API keys can have permissions to limit access. ([Immich API][1])

For your first read-only Igloo Photos integration, start with the minimum permissions needed for browsing. At minimum, you will likely need read permissions around albums and assets, for example:

```txt
album.read
asset.read
```

Depending on the exact endpoints you use, you may also need permissions for users, people, tags, memories, or search later. Do not enable upload/delete permissions yet unless you are intentionally adding write features.

## 2. How to configure the API key in Igloo

For development, use environment variables:

```env
IMMICH_BASE_URL=http://localhost:2283
IMMICH_API_KEY=your_api_key_here
```

Then your Igloo backend should call Immich using the `x-api-key` header. Immich documents `x-api-key: <apiKey>` as the API-key authentication header. It also supports `apiKey` as a query parameter, but the header is the cleaner option. ([Immich API][2])

Example with `fetch`:

```ts
const response = await fetch(`${process.env.IMMICH_BASE_URL}/api/albums`, {
  headers: {
    "x-api-key": process.env.IMMICH_API_KEY!,
    "Accept": "application/json",
  },
});

if (!response.ok) {
  throw new Error(`Immich request failed: ${response.status}`);
}

const albums = await response.json();
```

For Igloo, I would not expose this key to the React app. Keep it server-side.

The flow should be:

```txt
Igloo React app
  -> Igloo backend endpoint
    -> Immich API with x-api-key
```

For example:

```txt
GET /api/photos/albums
```

internally calls:

```txt
GET {IMMICH_BASE_URL}/api/albums
```

## 3. How to test the API key manually

Use `curl` first before writing any Igloo code:

```bash
curl -L \
  -H "Accept: application/json" \
  -H "x-api-key: YOUR_API_KEY" \
  "http://localhost:2283/api/albums"
```

Or, if your Immich server is on another machine:

```bash
curl -L \
  -H "Accept: application/json" \
  -H "x-api-key: YOUR_API_KEY" \
  "http://192.168.1.50:2283/api/albums"
```

If that works, your Igloo backend can use the same base URL and key.

## 4. How to get the OpenAPI JSON file

Immich’s official docs say the API documentation is generated from OpenAPI, and the generated SDK is based on `immich-openapi-specs.json`. ([Immich][3])

The file is in the Immich GitHub repo here:

```txt
open-api/immich-openapi-specs.json
```

GitHub shows the file at:

```txt
immich/open-api/immich-openapi-specs.json
```

and marks it as a large JSON file of about 705 KB. ([GitHub][4])

To download it:

```bash
curl -L \
  -o immich-openapi-specs.json \
  https://raw.githubusercontent.com/immich-app/immich/main/open-api/immich-openapi-specs.json
```

However, for your project, I would **not** blindly use `main` forever. Use the spec that matches the Immich version you are targeting.

For example, if your Immich server is version `v1.135.0`, download from that tag instead of `main`:

```bash
curl -L \
  -o immich-openapi-specs.json \
  https://raw.githubusercontent.com/immich-app/immich/v1.135.0/open-api/immich-openapi-specs.json
```

That keeps your generated client aligned with the Immich server you are actually running.

## 5. How to inspect the API

You have three practical options.

### Option A: Use the hosted Immich API docs

Use the published API docs for exploration:

```txt
https://api.immich.app
```

Immich’s docs point to this as the official published API documentation site. ([Immich][3])

This is best for reading endpoints manually.

### Option B: Open the JSON file in an OpenAPI viewer

Download `immich-openapi-specs.json`, then open it with tools like:

```txt
Swagger Editor
Redocly
Scalar
OpenAPI Generator
```

This is useful when you want local docs while developing Igloo.

### Option C: Generate a TypeScript client

Since you are using TypeScript heavily, you can generate a client from the OpenAPI file:

```bash
bunx @openapitools/openapi-generator-cli generate \
  -i immich-openapi-specs.json \
  -g typescript-fetch \
  -o src/lib/immich/generated
```

That said, for Igloo, I would probably start with a thin handwritten adapter instead of using the generated client everywhere. Generated clients can be noisy.

A good structure would be:

```txt
src/lib/immich/
  client.ts
  albums.ts
  assets.ts
  types.ts
  generated/   # optional
```

## Recommended first setup for Igloo

Start simple:

```env
IMMICH_BASE_URL=http://your-immich-server:2283
IMMICH_API_KEY=your_key
```

Create an Igloo server helper:

```ts
const immichBaseUrl = process.env.IMMICH_BASE_URL;
const immichApiKey = process.env.IMMICH_API_KEY;

export async function immichFetch(path: string, init?: RequestInit) {
  if (!immichBaseUrl) {
    throw new Error("IMMICH_BASE_URL is not configured");
  }

  if (!immichApiKey) {
    throw new Error("IMMICH_API_KEY is not configured");
  }

  const response = await fetch(`${immichBaseUrl}/api${path}`, {
    ...init,
    headers: {
      "Accept": "application/json",
      "x-api-key": immichApiKey,
      ...init?.headers,
    },
  });

  return response;
}
```

Then build your own Igloo endpoints on top of that.

My recommendation: use the OpenAPI file to understand the API and confirm DTOs, but expose your own small Igloo photo API to the frontend. Keep the Immich key and Immich-specific details server-side.
