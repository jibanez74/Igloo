Movie Watch Progress Implementation Summary

Completed

- Added backend storage for per-user movie watch progress in `movie_watch_progress`.
- Added SQL queries for reading progress, saving progress, clearing progress, marking watched, and marking unwatched.
- Added backend endpoints for:
  - GET `/api/movies/{id}/watch-progress`
  - PUT `/api/movies/{id}/watch-progress`
  - DELETE `/api/movies/{id}/watch-progress`
  - PUT `/api/movies/{id}/watch-progress/watched`
- Implemented backend validation and behavior:
  - requires auth
  - validates movie id
  - verifies the movie exists
  - rejects non-positive duration
  - clamps progress to `[0, duration]`
  - returns `200` with an empty state when no progress row exists
  - regular progress updates force `watched = false`
  - progress at 98% or higher marks the movie watched and clears progress
- Regenerated sqlc output and synced the embedded schema.
- Added frontend API helpers and query options for watch progress.
- Added a watched button to the movie details action row.
- Added play-page watch progress behavior:
  - fetch saved progress on load
  - show resume dialog when saved progress is eligible
  - resume via `start` for HLS
  - resume via direct `currentTime` seek for direct playback
  - clear progress when user chooses start from beginning
  - save every 15 seconds while actively playing
  - save on pause
  - save on ended
  - best-effort save on `pagehide` with `keepalive`

Verified

- `cd web && bun run build`
