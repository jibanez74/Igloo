HLS DB Streams Implementation Checklist

Goal:
- Move HLS stream/session creation to persisted DB stream rows instead of runtime ffprobe.
- Keep scanner as the only place that probes movie files.
- Split movie runtime into:
  - run_time for UI-facing display
  - one exact duration field for HLS/session use
- Do not handle fsnotify, stale DB recovery, or fallback ffprobe in this work.

Implementation rules:
- Follow DRY. Do not duplicate stream-selection or codec-filter rules.
- Follow best Go practices:
  - keep helpers small and explicit
  - keep error handling readable and on its own lines
  - wrap errors with useful context
- Keep frontend behavior stable unless a change is explicitly required by the plan.
- Fix affected unit tests and keep them focused and low-noise.
- All constants in the backend go in constants.go
- All constants in the client go in constants.ts
- Never define types inside of functions
- Avoid comments unless they are strictly necessary
- In the backend, helper functions should go in the helpers package unless for some reason they can’t.
